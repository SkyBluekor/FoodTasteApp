# FoodTasteApp 음식 사진 번호 불일치 — 2026-11-02 점검

## 확인된 문제

- 화면에 '쑥갓나물무침'으로 표시되는 음식은 XML 및 데모 DB 생성 순서상 `FoodNum=1257`이다.
- `Assets/Images/FoodImg/1257.jpg`를 직접 열어 확인한 결과 **콩가루를 묻힌 떡 사진**이다.
- `FoodImageCatalog.Get(1257)`는 매칭표보다 `1257.jpg`를 우선 사용한다. 따라서 매칭 CSV에서 다른 대표 사진을 지정해도 원래 JPG가 그대로 표시될 수 있다.
- 주변 파일을 추출해 확인해도 `1256.jpg`는 코울슬로가 아닌 초록색 떡 사진, `1261.jpg`는 갓김치가 아닌 흰색 떡 사진으로 보였다.
- 보다 넓은 샘플도 불일치: `1000.jpg`는 라면(원본 XML에서는 초콜릿 케이크), `1050.jpg`는 죽(닭고기 칼국수), `1100.jpg`는 다른 볶음/찜 요리(순대국)로 보였다.

## 즉시 조치

육안 확인으로 **명백히 잘못된 26개** 번호를 `Assets/Resources/FoodImageRejected.csv`에 기록했다.

`FoodImageCatalog`는 다음 순서로 사진을 선택한다.

1. 해당 FoodNum이 거부 목록에 있으면 `FoodImageFallback.png`를 표시하고 경고한다.
2. 그렇지 않으면 기존의 FoodNum 번호 이미지와 대표 이미지 매핑을 그대로 사용한다.
3. 대표 매핑의 목표 번호가 거부 목록에 있으면 그 사진을 재사용하지 않고 fallback을 표시한다.

원본 JPG와 `FoodImageMapping.csv`, 영양정보 XML, MySQL 데이터, 검색/평가/추천 로직은 수정하지 않았다. 원본 JPG 파일은 이후 올바른 이름에 연결할 수 있도록 보존한다.

## 아직 남아 있는 범위

- 이 조치가 원본 이미지 **전체의 정확성을 보증하지는 않는다.** 이번 확인은 샘플에 한정한다.
- 특히 번호 1000대 이후의 기존 사진은 서로 다른 자료의 번호가 섞여 있을 가능성이 있어 **음식명–실제 사진을 일대일로 시각 검수**해야 한다. 현재로서는 틀린 사진을 다른 음식 번호로 자동 재배정해서는 안 된다.
- 정확한 음식 사진이 마련되면 `FoodImageRejected.csv`에서 해당 번호를 제거하고 `{FoodNum}.jpg/png`를 교체하거나 검증된 대표 매핑을 적용한다.
- 실제 Unity 화면에서 fallback 표시와 음식 상세/검색/추천 화면을 검증해야 한다.
